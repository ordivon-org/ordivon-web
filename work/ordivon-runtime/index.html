Agent infrastructure · Effect commitment · Trusted-local execution

Commit one Agent action to reality without losing what happened.

Ordivon Runtime owns the deterministic boundary between an Agent decision and local machine execution. It binds one operation to exact source and executable state, dispatches one process tree at most once per Attempt, retains bounded evidence, preserves uncertainty, and supports recovery after clients, services, or sessions disappear.

Central question

Which execution facts cannot safely be reconstructed after interruption?

An Agent may reconstruct its plan, but it cannot infer whether a process crossed the physical dispatch boundary, which exact source world it used, whether cancellation won a race, whether a response was lost after commitment, or which retained bytes belong to the original operation.

The Runtime persists only the facts required to identify, observe, cancel, reconcile, recover, and eventually release that work. Linux, systemd, Git, SQLite, and digest-bound files remain the strongest owners of the mechanics beneath it.

Arbitrary command execution remains effect-opaque. Process success does not prove an external effect occurred exactly once, an Artifact does not prove a claim is correct, and Runtime completion does not prove the user's goal is satisfied. Ambiguous work is never silently redispatched.

Boundary

Workspace isolation protects code state; it is not a sandbox for untrusted code.

An authenticated Agent receives the installed service user's trusted-local authority. The Runtime commits and recovers execution; it does not reduce root authority, adjudicate model correctness, own Goal or Task continuity, or guarantee exactly-once effects inside an arbitrary executable. Untrusted work requires a separate VM or container boundary.

Evolution

The ten-tool core became a production effect boundary without becoming a general workflow platform.

  1. 23 Jul 2026
    Close the M0–M7 ten-tool core.

    The first release established Workspace operations, durable execution, cancellation, Artifacts, and restart recovery.

  2. Agent UX
    Add reconnectable Workspaces and structured ExecPlan; retire overlapping Patch.

    Repeated engineering friction justified durable recovery and progress primitives. Production evidence later showed Patch duplicated mutation and script editing, so it left the public surface.

  3. Effect Kernel
    Bind request identity separately from world commitment.

    Source-state commitment, pre-spawn validation, explicit ambiguity, and opaque-effect limits made the physical boundary precise.

  4. 28 Jul 2026
    Close the production lifecycle.

    Explicit execution environments, external caches, daily retention, repair, secret-free status, receipted deployment, and historical Workspace reclaim turned the Runtime into a maintainable service.
