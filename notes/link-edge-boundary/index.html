Architecture report / Network and external execution

Separating connectivity from external execution

A network path and a network-side capability fail in different ways. Ordivon Link owns path evidence, selection, transport, and local recovery. Ordivon Edge owns signed hosted effects, private Artifacts, receipts, leases, and release recovery.

Architecture report · Ordivon Link + Edge · Published 28 July 2026 · 8 min read · By zycxfyh

The original Edge concept combined overseas reachability, VPN behavior, transport experiments, remote execution, browser capabilities, and Cloudflare infrastructure. That bundle looked coherent because every problem involved the network. In operation, however, two independent state owners emerged: one decides how a local device can reach an endpoint; the other executes a bounded capability in an externally hosted environment.

Connectivity is evidence about a path

A path is not simply online or offline. DNS may resolve while QUIC fails. One VPN route may reduce latency to Tokyo and worsen Cloudflare Tunnel stability. A connection may complete quickly but stall during sustained transfer. An endpoint may be reachable directly while a process inherits an unrelated proxy.

Link therefore observes local route, DNS, interface, VPN, WARP, MTU, Windows and WSL state, Tunnel health, Runtime MCP health, and named endpoint probes. It persists sanitized snapshots and state changes rather than raw secrets or command output.

Selection and transport remain replaceable

Measurements reduce into explicit route evidence. A route label records controlled conditions; it does not claim perfect knowledge of the physical packet path. Automatic selection remains deferred until repeated evidence can justify policy and explain failure.

The Baseline v0 wire contract and Quinn/rustls mTLS reference transport are isolated from observation and presentation. The read-only Web console cannot acquire relay code or mutate routes. The transport reference cannot inspect VPN state or write the observation database.

Explicit VPN execution is not global route mutation

Link includes a root-only WireGuard namespace controller for selected commands. It creates a separate network namespace, applies configuration transactionally, executes the named process, and tears the namespace down without moving the WSL root route, Runtime, MCP service, or Cloudflare Tunnel.

This narrow control path preserves the current trusted-root operating model while avoiding a hidden machine-wide connectivity change.

Hosted execution is a different commitment problem

Edge receives a signed Request ID and executes allowlisted Fetch or bounded Browser Run inside Cloudflare. A caller may lose the response after the Worker committed. A stale executor may finish after its lease expired. A new release may be accepted by the control plane before the client times out. Artifacts and receipts may have different retention periods.

Those failures require authoritative request state, generation leases, conditional writes, private Artifact namespaces, deterministic replay, policy fingerprints, and version-bound release receipts—not local route selection.

One request state fences competing executors

Edge creates one conditional requests/v2 pending object containing the semantic request digest, capability and policy versions, Worker version, lease generation, private lease token, and expiration. Final commitment replaces that object with the complete Receipt using the current ETag.

An expired lease can be taken over only when policy and capability versions still match. The generation increments, and every Artifact key includes that generation. A stale executor therefore cannot commit against the new ETag or delete the newer generation's output.

Ambiguous storage writes are reconciled

If an R2 commit call throws after the platform may have accepted the write, Edge rereads authoritative state. A matching committed Receipt is success. Pending or different-generation state causes the executor to clean only its own generation and fail closed.

If immediate cleanup fails, a bounded tombstone records only the Request ID, capability, generation, Artifact keys, reason, and time. The GC controller validates namespace and generation before deletion.

Policy identity belongs in every lease and receipt

The effective hostname allowlist and checked-in policy configuration produce one fingerprint. Expired work cannot cross that fingerprint even when the capability schema is unchanged. Receipts therefore answer not only what executed, but under which policy and Worker version.

Request identity and receipt replay remain available for 90 days. Capability Artifacts live one day longer so a replayable Receipt does not outlive its referenced bytes.

Release recovery is part of the effect plane

Edge release tooling uploads one exact Worker version, performs a zero-percent traffic smoke through version override, validates the capability surface, promotes, and records the result. Control-plane response loss is reconciled through Cloudflare state, and resumed releases remain bound to the original Worker source identity.

This is not a generic deployment framework. It exists because hosted capability identity and release identity directly affect the meaning of receipts.

The boundary prevents two forms of accidental authority

Without the split, a local status console could gradually gain VPN, route, relay, Worker, R2, and browser authority. Conversely, a hosted Worker could begin making assumptions about the user's local route, proxy, or Tunnel. Link and Edge now expose narrow contracts instead.

  • Link asks which path is usable and recoverable.
  • Edge asks which hosted capability should execute and what evidence proves its result.
  • Runtime asks how a local Agent process is committed and recovered.

What remains open

Link has not implemented automatic route execution, automatic failover, production certificate lifecycle, public relay endpoints, mature sing-box or Xray adapters, or seven-day controlled evidence. Edge has not become a general remote node fleet, arbitrary browser automation service, or open proxy.

Future work should cross the boundary only when a concrete capability can state which facts Link supplies, which effect Edge commits, which receipt proves the result, and which component owns recovery after ambiguity.

This report describes the current Link and Edge boundary on 28 July 2026. Current path, Worker, policy, Artifact, and release facts remain in the two repositories and their operational evidence.
