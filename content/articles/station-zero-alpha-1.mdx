<h2 id="a-playable-release-not-a-platform-promise" data-toc="A playable release">A playable release, not a platform promise</h2>

<p>Station Zero <code>v0.1.0-alpha.1</code> is the first source-playable Ordivon Game release. It is a bounded developer Alpha: one deterministic mission, one verified player journey, exact replay, evidence-linked diagnosis, immutable deployment, same-Case comparison, reload recovery, and an archive that can be unpacked and reverified from clean state.</p>

<div className="article-thesis"><p>The release unit is not a screenshot or a successful local database. It is one exact source tree, one evaluated-input set, one archive digest, and one journey another machine can reproduce.</p></div>

<h2 id="the-player-loop" data-toc="The player loop">The player loop</h2>

<p>The release journey is intentionally narrow:</p>

<ol>
  <li>Create or open a deployment.</li>
  <li>Run the Station Zero mission through verified Team Ticks.</li>
  <li>Reach a terminal victory or failure.</li>
  <li>Move to an earlier World revision and inspect exact state.</li>
  <li>Open diagnosis and follow evidence-linked claims.</li>
  <li>Clone the deployment.</li>
  <li>Change one bounded coordination profile.</li>
  <li>Run again and compare inputs and outcomes.</li>
  <li>Reload the browser and recover the same Run.</li>
</ol>

<p>The product surface stays small: Mission, Replay, Diagnosis, Compare, and Deploy Again. Raw Commands, logs, internal identifiers, engineering receipts, and earlier milestone controls remain behind the explicit debug surface.</p>

<h2 id="one-input-changed-the-terminal-outcome" data-toc="One input changed the outcome">One input changed the terminal outcome</h2>

<p>Both retained Runs use the same <code>power-constrained</code> Scenario Case. The only evaluated-input difference is <code>coordinationProfileId</code>.</p>

<p>The comparison reports a score delta of 1,090 and a minimum-battery delta of two. It does not infer a universal coordination law. It proves that a typed, immutable, measured product input can change a verified outcome while every other evaluated input remains bound.</p>

<h2 id="replay-and-diagnosis-are-release-features" data-toc="Replay and diagnosis">Replay and diagnosis are release features</h2>

<p>The victory Run contains 19 point-in-time frames, 380 evidence nodes, 736 evidence edges, and 12 bounded key turns. The failure Run contains 22 frames, 443 nodes, 859 edges, and the same 12-key-turn cap.</p>

<p>Diagnosis does not ask a model to invent causality. Claims carry one of four evidence classes:</p>

<div className="surviving-invariants" aria-label="Diagnosis evidence classes">
  <span>verified direct</span><span>verified contributor</span><span>counterfactual sensitive</span><span>context only</span>
</div>

<p>A verified contributor is not promoted to the unique cause. Counterfactual sensitivity is a bounded one-step legal-alternative test, not a statistical causal estimate. Evaluation timeout is not relabelled as a mission failure. Raw Context and Artifact bodies remain behind detail APIs rather than inflating every frame.</p>

<h2 id="what-the-alpha-proves" data-toc="What the Alpha proves">What the Alpha proves</h2>

<ul>
  <li>A deterministic World and persistent multi-Agent Host can support a small player product rather than only an engineering harness.</li>
  <li>Replay, diagnosis, comparison, and reload recovery can be release-critical instead of optional debugging tools.</li>
  <li>One coordination-only input can be changed and compared without silently changing the Scenario or ruleset.</li>
  <li>Fixture cognition can keep release verification deterministic while live Codex and Hermes remain optional experimental paths.</li>
  <li>A source release can preserve identity beyond a Git tag through tree, evaluated-input, archive, and release digests.</li>
</ul>

<h2 id="what-the-alpha-does-not-prove" data-toc="What it does not prove">What the Alpha does not prove</h2>

<p>The Alpha does not establish that multi-Agent architecture is superior to an equal-budget single Agent. It does not claim that Codex or Hermes will complete every Scenario. It does not provide hosting, accounts, multiplayer, 3D, modding, a generic game platform, or a stable public compatibility promise.</p>

<p>The release-critical path uses deterministic Fixture cognition. That is deliberate: a downloadable release should not fail because a remote model is unavailable, expensive, changed, or rate-limited. Live Provider trajectories remain research evidence, not a prerequisite for opening the game.</p>

<h2 id="the-next-game-question" data-toc="The next game question">The next game question</h2>

<p>The strongest next experiment is not more presentation. It is the equal-budget single-Agent versus multi-Agent ablation already required by the Game research dossier. The same World, information budget, Tool access, action budget, and player surface must compare whether persistent specialists, typed communication, and explicit authority create capability that a strong classical or single-Agent baseline cannot reproduce economically.</p>

<p className="article-closing">Station Zero is small by design. Its value is that every visible outcome can be replayed, inspected, compared, and tied back to the exact release that produced it.</p>
