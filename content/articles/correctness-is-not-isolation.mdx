<InBrief claim="A system can preserve effect-correctness rules without being isolated from a hostile administrator on the same machine." evidence="E2 public · exact local owner experiment retained; no public canonical Finance record is currently available" scope="Finance C2-L single-machine disabled staging profile">
  <p>C2-L did not weaken the financial-effect protocol. It stopped using remote location as a proxy for two different assurances.</p>
</InBrief>

<h2 id="the-old-rule-sounded-safer" data-toc="The old rule sounded safer">The old rule sounded safer</h2>

<p>The original instinct was simple:</p>

<blockquote>Real money should only move through an independently administered remote executor.</blockquote>

<p>That rule has obvious appeal. If the Agent workstation cannot read the trading credential, replace the signer, rewrite the executor, or alter its policy, a compromised Agent has fewer ways to seize authority.</p>

<p>But the rule also smuggles in a stronger claim:</p>

<blockquote>Without remote administration, the effect itself cannot be correct.</blockquote>

<p>C2-L was designed to attack that second claim.</p>

<h2 id="one-word-safety-was-hiding-two-axes" data-toc="Safety was hiding two axes">One word—safety—was hiding two axes</h2>

<p>The experiment split the question into two independent assurances.</p>

<h3>Axis 1: effect correctness</h3>

<p>Can the system preserve:</p>

<ul>
  <li>the exact economic intent and world binding;</li>
  <li>one durable dispatch permission;</li>
  <li>no blind retry after ambiguity;</li>
  <li>raw evidence and exact replay;</li>
  <li>reconciliation before another consequence;</li>
  <li>explicit separation between preparation and submission?</li>
</ul>

<h3>Axis 2: credential and administrator isolation</h3>

<p>Can the Agent-admin principal read or replace:</p>

<ul>
  <li>venue credentials;</li>
  <li>private signer authority;</li>
  <li>TrustPolicy;</li>
  <li>executor release bytes;</li>
  <li>service configuration or ledger administration?</li>
</ul>

<p>These questions are related in a deployment threat model. They are not the same invariant.</p>

<h2 id="the-root-probe-destroyed-the-isolation-claim" data-toc="Root destroyed the isolation claim">The root probe destroyed the isolation claim</h2>

<p>The current Runtime <code>trusted_local</code> profile executes as root.</p>

<p>C2-L performed a metadata-only authority probe and established that this principal could read or write the root-owned executor credential files, TrustPolicy, and systemd unit.</p>

<p>Therefore the current single-machine profile cannot honestly claim protection from a malicious or compromised root Agent.</p>

<div className="article-thesis"><p>Systemd hardening, read-only release bytes, DynamicUser, and LoadCredential can reduce accidental coupling. They cannot create an adversarial boundary against the same root authority.</p></div>

<p>That part of the old safety story was falsified.</p>

<h2 id="then-the-effect-protocol-refused-to-fail-with-it" data-toc="Effect correctness survived">Then the effect protocol refused to fail with it</h2>

<p>The next question was whether losing hostile-root isolation also destroyed the effect-correctness properties.</p>

<p>On the disabled C2/v3 staging surface, the retained protocol still enforced:</p>

<ul>
  <li>Package v3 / Grant v2 / EffectAdmission v2 / commit@5 version closure;</li>
  <li>Decision, Proposal, Request, and world-gate identity before effect admission;</li>
  <li>purpose-separated signer roles;</li>
  <li>immutable versioned executor release with no historical executable fallback;</li>
  <li>a loopback-only narrow HTTP surface;</li>
  <li>exactly one durable dispatch permission;</li>
  <li>exact replay before mutable venue reads;</li>
  <li>no second POST after a consumed dispatch claim;</li>
  <li>raw evidence retention and reconciliation-first ambiguous outcomes;</li>
  <li>a disabled-first kill boundary.</li>
</ul>

<p>The focused evidence recorded:</p>

<p>The correct conclusion became narrower:</p>

<blockquote>Remote location is one way to buy stronger credential/admin independence. It is not itself a law of effect correctness.</blockquote>

<p>This is why “remote” and “safe” are poor synonyms.</p>

<h2 id="the-experiment-also-found-two-real-blockers" data-toc="The experiment found real blockers">The experiment also found two real blockers</h2>

<p>C2-L did not use the narrower architecture claim as permission to activate trading.</p>

<p>The exact executor credential installed in the disabled staging profile did not match the separately valid canonical Read+Trade/no-Withdraw profile. A read-only account-config check using the executor credential returned <strong>401 Invalid OK-ACCESS-KEY</strong>.</p>

<p>The experiment therefore refused to infer executor fitness from a different credential merely because that other credential belonged to the same account.</p>

<p>Local private signer authority was also not provisioned or verified.</p>

<p>These were not cosmetic checklist items. They were current deployment facts, and they remained blockers.</p>

<h2 id="preparation-is-not-submission" data-toc="Preparation is not submission">Preparation is not submission</h2>

<p>The current policy separates:</p>

<pre tabIndex={0}><code>{`mechanically qualified preparation
≠ authorization to submit a live effect`}</code></pre>

<p>The disabled staging executor used an unreachable API base, exposed no raw authenticated write route, and returned <code>executor-disabled</code> before venue action. No financial write occurred during C2-L.</p>

<p>Even if <code>localEffectCorrectnessQualified=true</code>, a live canary still requires a separate transition proving exact credential permissions, usable signers, real venue reachability, and live reconciliation.</p>

<h2 id="why-this-matters-beyond-finance" data-toc="Why this matters beyond Finance">Why this matters beyond Finance</h2>

<p>Engineering systems often collapse several assurances into one prestigious mechanism:</p>

<ul>
  <li>containerized → isolated;</li>
  <li>remote → independent;</li>
  <li>encrypted → authorized;</li>
  <li>transactional → correct;</li>
  <li>redundant → reliable.</li>
</ul>

<p>Sometimes the mechanism contributes to the assurance. The error is treating the mechanism's presence as proof of every property associated with it.</p>

<p>C2-L's useful method is to name the assurance separately, attack it directly, and keep only the part the evidence actually supports.</p>

<h2 id="when-remote-independence-is-still-worth-paying-for" data-toc="When remote independence is worth it">When remote independence is still worth paying for</h2>

<p>Independent administration remains valuable when the threat model includes a hostile Agent with root on the workstation, when capital size makes workstation compromise unacceptable, when organizational separation is required, or when operational consequence justifies the extra substrate.</p>

<p>The experiment removed a universal prerequisite. It did not remove the high-assurance profile.</p>

<h2 id="the-surviving-rule" data-toc="The surviving rule">The surviving rule</h2>

<p>After falsification, the Finance rule is smaller and more explicit:</p>

<blockquote>Every deployment must prove effect correctness. Credential/admin isolation is an additional deployment assurance whose required strength depends on the threat model and consequence severity.</blockquote>

<p className="article-closing">A stronger system is not one that calls every concern “safety.” It is one that can say exactly which safety property has been proved, which one has failed, and which one has not yet been attempted.</p>
