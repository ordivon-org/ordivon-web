# R2 P0 — Editorial Entry and Distribution

Date: 31 July 2026  
Baseline: `main@a3b71af29a54778e05d037671f7b349d80c9f6f5`  
Scope: the highest-leverage public entry surfaces identified by the R1 copy audit.

## Objective

R2 P0 changes the order in which readers encounter Ordivon:

```text
real failure or demonstrated capability
→ why it matters
→ current judgment
→ architecture and formal terminology
→ complete evidence
```

The work does not weaken technical precision or remove the research model. It moves internal schema language below a concrete problem, result, or reading promise.

## Changes

### Navigation and naming

- Added `Projects` to desktop navigation.
- Standardized the `/now` label as `Now` across header, footer, metadata, and page hero.
- Retained `About` as contextual navigation rather than a primary desktop destination.

### Global positioning and metadata

- Changed the global title to `Ordivon — Durable work for AI agents`.
- Replaced formal object lists in the global description with a plain statement about continuation, recovery, and verification across sessions, processes, machines, and providers.
- Rewrote System, Research, Projects, About, Now, Writing, RSS, and article social descriptions where entry language was needlessly internal.

### Homepage

- Retained `Work should survive the intelligence that started it.` as the primary thesis.
- Defined Ordivon as independent research and engineering for durable agent work.
- Replaced the former architecture-first proof with the H1–H5 live replacement result:
  - four real provider runs;
  - both Codex→Hermes and Hermes→Codex replacement orders;
  - stale completion, missing artifact, and response-loss faults.
- Reframed the four state owners as four layers that preserve one recoverable trajectory.
- Changed navigation CTAs from generic exploration to explicit reader promises.

### Writing entry

- Added one explicit `Start here` publication.
- Added two evidence-first flagship reports.
- Added three editorial reading paths:
  - Start with Ordivon;
  - Agent architecture;
  - Experiments and failures.
- Preserved Question-derived navigation and the chronological archive below the editorial entry layer.
- Replaced content-model counts with publication-type counts.

### Publication framing

Reframed three titles that led with internal sequence codes or broad generic language:

- `What H1–H5 Proved About Durable Agent Work`
  → `What Survived When Codex and Hermes Replaced Each Other Mid-Task`
- `Ordivon Runtime after the core`
  → `How Ordivon Runtime Grew Beyond Its Ten-Tool Core`
- `Why Ordivon matters in the AI era`
  → `AI Agents Need More Than a Good Conversation`

The underlying slugs, dated arguments, evidence, and source links remain unchanged.

### Social distribution

- Added one 1200×630 PNG social card for every registered article.
- Article Open Graph and Twitter metadata now reference the article-specific asset.
- Added `scripts/generate-social-cards.py` and `pnpm social:generate`.
- The generator derives all card content from `content/articles/registry.ts`; no second social-card manifest was introduced.
- Assets are committed because the site is a static GitHub Pages export and should not depend on request-time image generation.

## Verification contract

R2 P0 requires:

- TypeScript generation and type checking;
- ESLint;
- production static export;
- all registered article routes;
- all registered social image routes;
- homepage and Writing editorial assertions;
- mobile and desktop overflow checks;
- focused accessibility checks;
- metadata inspection for global and article-specific social tags.

Local static verification covers the first five items and output metadata. GitHub CI owns the complete Playwright matrix when the isolated local Workspace does not contain a Chromium binary.

## Deliberate non-goals

R2 P0 does not yet perform the deeper page-role revisions from the R1 P1/P2 queue:

- full Now editorial restructuring;
- About origin and authorship narrative;
- capability and maturity fields on Projects cards;
- one end-to-end work trajectory above the System ontology;
- a `Start here` research frontier before the Research explorer;
- full cross-site capitalization and terminology normalization.

Those changes should proceed only after the new entry layer survives production use and review.
